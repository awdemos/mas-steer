# SAFETY.md — Safe Operation of MAS-Steer

MAS-Steer is a research tool for finding and evaluating neuron interventions in
frozen language models. It is designed to make steering search auditable and
adversarially tested, but the tool itself does not prevent a user from finding
interventions that produce harmful outputs. This document describes how to run
it safely, what the built-in safeguards are, and what remains the operator's
responsibility.

## What MAS-Steer does

- Searches for small sets of activation-space edits that elicit a behavior on a
task family.
- Evaluates every candidate against both task prompts and control prompts to
penalize collateral damage.
- Archives the winning intervention as replayable JSON.
- By default uses a deterministic mock backend; real backends are wired in by
the operator.

## What MAS-Steer does not do

- Filter, classify, or block task prompts by content.
- Guarantee that a found intervention is safe, fair, or aligned.
- Prevent a candidate from steering a model toward disallowed outputs.
- Handle secrets, tokens, or model weights securely on your behalf.

## Built-in safeguards

| Safeguard | Purpose | Location |
|-----------|---------|----------|
| Control-task penalty | Discourages interventions that break unrelated capabilities | `arena::scoring::Score::from_components` |
| Dose clipping | Limits per-candidate intervention strength during search | `agent::search::run_search` |
| Output path traversal guard | Prevents the CLI from writing outside the intended directory | `mas-steer-cli/src/main.rs` |
| Prompt file size limit | Prevents unbounded memory use during `eval` | `mas-steer-cli/src/main.rs` |
| Config validation | Rejects nonsensical search parameters before they can panic | `agent::search::validate_config` |
| `unsafe_code = forbid` | Eliminates unsafe Rust from the workspace | workspace `Cargo.toml` |

These are engineering guards, not content safety filters.

## Operational safety guidelines

### 1. Run in an isolated environment

- Use a local container, VM, or sandboxed user account.
- Do not run searches against production model serving endpoints.
- Keep model checkpoints and generated artifacts inside the sandbox.

### 2. Treat generated champions as untrusted code

A champion JSON file contains only floating-point doses and coordinate indices,
but replaying it against a real model can produce arbitrary text. Before sharing
or deploying a champion:

- Inspect the intervention sites and doses.
- Re-evaluate on held-out prompts, including adversarial ones.
- Do not load champions from untrusted sources without review.

### 3. Choose task families deliberately

The arena includes refusal-style and sentiment-style task families. When
searching for capabilities rather than safety behaviors, avoid families that
intentionally probe harmful or disallowed content unless that research is
explicitly authorized and monitored.

### 4. Do not expose the CLI to untrusted users

The CLI is a local research tool. If you build a service around it:

- Run searches in short-lived, isolated workers.
- Validate and sanitize all file paths and config values at the service layer.
- Apply output quotas, timeouts, and rate limits.
- Never pass user input directly into `--config` or `--output` without validation.

### 5. Handle model weights and tokens responsibly

- Pin model revisions and verify checksums.
- Store Hugging Face tokens, API keys, and weights outside the repository.
- Use restrictive file permissions (`0o600` for tokens, `0o700` for model dirs).
- Do not commit weights, tokens, or champion artifacts to version control.

### 6. Review outputs before publication

Search logs, champion JSON, and sample generations may contain:

- Potentially harmful text produced during steering.
- Prompts that were generated by the adversarial challenger.
- Stack traces or environment details if a crash occurs.

Sanitize or redact these before sharing them publicly.

## Adversarial review

The latest adversarial security review is at
`reports/adversarial-mas-steer-2026-11-01.md`. It covers file-path traversal,
unbounded input reads, and search configuration validation. Content safety
(guardrails against generating harm) is out of scope for that review and is the
operator's responsibility.

## Incident response

If a steering search produces unexpectedly harmful or persistent model behavior:

1. Stop the running process.
2. Do not deploy or share the champion JSON.
3. Document the task family, model, and hyperparameters.
4. File an internal issue and, if appropriate, email hello@neuronengineering.dev.

## Responsible disclosure

Security vulnerabilities in the tooling itself should be reported privately to
hello@neuronengineering.dev per `SECURITY.md`. Do not open public issues for
undisclosed security bugs.
